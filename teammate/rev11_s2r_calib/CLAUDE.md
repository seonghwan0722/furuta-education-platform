# rev11 Furuta 심투리얼 (Raspberry Pi에서 실행하는 Claude Code용 안내)

**응답은 항상 한국어로.**

## 목표
팀원이 학습한 `handoff/rl/rev11/sac_rev11.zip` 정책을 **바꾸지 않고** 실기에 올린다.
방법: 실기에서 진자 각도·모터 전류/토크를 기록 → 같은 입력을 MuJoCo에 넣어 **실기 vs 시뮬 그래프**를 겹쳐 그림 →
시뮬 물성치를 보정 → 보정된 시뮬에서 정책 평가 → 실기 실행 → 다시 비교·보정 (반복).
진자는 분리하지 않는다. 정책 재학습은 이 작업 범위가 아니다(필요하면 보정된 물성치를 팀원에게 전달).

## 세션 시작 점검 (모든 실험 스크립트가 자동 실행: `pi_host/session.py` preflight)
단독 실행은 `python3 pi_host/session.py check`. 점검은 읽기 명령(0x9A/0x92/0x9C)만 보낸다.
1. can0 UP, ERROR-ACTIVE, 1 Mbps, 다른 CAN 송신 프로세스 없음. 다르면 **멈추고 사용자에게 알림**(사용자가 재설정).
2. CAN 버스를 1 s 듣기만 해서 우리가 보내지 않은 0x141/0x241이 보이면 다른 쪽이 쓰는 중 → 바로 중단.
3. 0x92 시작 각도를 기록하고 이전 세션 마지막 각도(`pi_host/state/session_state.json`)와 비교해 몇 바퀴 바뀌었는지 알림(케이블 확인).
4. 진자 정지 RAW가 영점 식 `session.zero_raw(0x92 각도)`(현재 2034.2 + 12.5·cos(θ − 136°), 2026-11-20)과 10카운트(0.9°) 넘게 다르면 알림(재장착 확인), 0.5 s 변동 6카운트 초과면 "흔들리는 중".
   (이력: 처음엔 고정 영점 2027과 20카운트 기준.)
5. 실험 기록 파일 이름은 `pi_host/logs/<실험>_YYYYmmdd_HHMMSS.csv` .

## 안전 규칙 (반드시 지킬 것)
- **모터를 움직이는 명령(0xA1 등)은 실행 전에 사용자에게 무엇을 할지 말하고 확인을 받는다.** 사용자가 실기 옆에 있어야 한다.
- 매 세션 시작 시 `ip -details link show can0`로 `ERROR-ACTIVE`, `bitrate 1000000` 확인. 500000으로 바뀌어 있으면
  `sudo ip link set can0 down && sudo ip link set can0 up type can bitrate 1000000`.
- **0xB3은 쓰지 않는다**(2026-11-18 사용자 결정, 모터 값은 0 = 꺼짐). 원래 하던 명령만 보낸다.
  꺼져 있으면 Pi가 멈춰도 모터가 마지막 토크를 유지하므로, 토크 시험은 짧게 하고 사용자가 옆에서 전원을 끊을 수 있게 한다.
- 스크립트는 종료(정상·예외·Ctrl+C) 시 반드시 토크 0 → 0x81 정지 → 0x78 브레이크 잠금 → (0x9C로 팔 < 50 dps 다시 확인되면) 0x80 출력 끄기를 보낸다.
  (0x80 추가: 2026-11-20 사용자 결정, 대기 중 MOS 발열 대책. 이력: 그 전에는 0x78 까지.)
- iq 절대값 상한을 코드에 둔다(시험 초반 0.8 A 이하).
- CAN 명령은 한 프로세스에서만 보낸다(동시에 두 곳에서 보내면 버스가 꼬임).
- **can0이 저절로 꺼지거나 500 kbps로 바뀌는 원인(2026-11-18 journalctl로 확인)**: PC(MATLAB/Simulink, SSH)에서
  배포한 `~/MATLAB_ws/R2026b/furuta_pi_*.elf`가 시작할 때마다 `sudo ip link set can0 down` → `up type can bitrate <모델값>`
  → `txqueuelen 65536`을 실행한다(`MW_SocketCAN_raspi.c`). 500000은 그 모델 설정값이고, 그 프로그램은 자기도 모터에 CAN 명령을 보낸다.
  12:21~16:18 사이 43번. 16:16~16:18에는 `furuta_pi_motor_output_drive.elf`가 이 세션 실험과 겹쳐 실행됨.
  → **실험 중에는 Simulink 배포/External mode를 쓰지 않는다.** `can0.service`(부팅 시 1 Mbps 설정) 자체는 정상.
- 모든 실험 스크립트는 `pi_host/canguard.py`를 쓴다: 시작 시 `full_check()`(UP, ERROR-ACTIVE, 1 Mbps, 다른 CAN 송신 프로세스 없음),
  송신마다 `fast_check()`(operstate), 수신한 0x141 프레임이 있으면(=다른 프로세스가 모터에 명령) 즉시 중단.

## 하드웨어와 프로토콜 (확인된 값)
- 모터 RMD-X6-P20-60-E, CAN can0 1 Mbps, 요청 0x141 / 응답 0x241. 프로토콜 MyActuator RMD-X V4.01.
  - 0x77 브레이크 해제, 0x78 잠금, 0x80 끄기, 0x81 정지, 0x9A 상태1(온도, MOS온도, 브레이크, 전압 0.1V, 에러).
  - 0xA1 토크: DATA[4..5] = iq int16 LE, 0.01 A/LSB. 응답: DATA[1] 온도, [2..3] iq 0.01 A, [4..5] 속도 1 dps, [6..7] 각도 **1°**.
  - 0x92 다회전 각도: DATA[4..7] int32 LE, **0.01°**.
  - 0xB3 통신 끊김 보호: DATA[4..7] uint32 LE, ms. 0이면 꺼짐. ROM에 저장됨.
  - 0x88(ON) 명령은 V4.01에 없다. 보내지 말 것.
- 진자 AS5600 I2C 버스 1, 주소 0x36, RAW ANGLE 레지스터 0x0C(12비트). 아래로 매달림 RAW = 2027(2026-11-18 진자 정지 상태 재측정, 이전 2070은 틀림) — **이력**: 영점은 팔 각도에 따라 바뀜, 현재 식은 '받침 수평 조정 후 영점 재측정(2026-11-20)' 항목. 도립 ±π 확인됨.
- 부호 규약(2026-11-18 변경): 시뮬 동역학이 좌우 대칭(M00(α)=M00(−α), M01(α)=M01(−α), G1(α)=−G1(−α), 오차 2e-4 이하)이라
  "시계/반시계"가 어느 쪽인지는 필요 없다. **θ_sim = +(0x92 각도 − 시작 각도), τ_sim = +iq 방향 (토크·θ 반전 없음).**
  alpha_sign은 손 시험(보는 방향, 손으로 진자 밀기) 대신 **자동 시험 `pi_host/auto_sign_test.py --go`**로 정한다:
  iq +60을 0.2 s 펄스 → (a) 0x92 변화가 양수이고 0xA1 각도 변화·속도 적분과 일치(0x92 단위 확인),
  (b) 펄스 직후 α가 음수면 alpha_sign=+1, 양수면 −1. 근거: 모델 관성으로 정지·α=0에서 α̈ = −0.62·θ̈ (+τ이면 α가 먼저 음수).
  (이전 손 시험 결과는 팔이 아니라 진자를 돌린 것이라 모두 무효.)
  **결과(2026-11-18 16:39, `pi_host/logs/auto_sign_20261118_163941.csv`)**:
  (a) 펄스 구간 Δ0x92 +18.58°, Δ0xA1 각도 +18°, ∫속도 +18.0° → +iq에서 0x92 증가, **0x92 = 0.01°/LSB 확인**.
  (b) 펄스 시작 14 ms 뒤부터 α가 단조 감소(raw 2052→1981, 200 ms), 토크를 끊자 반전 → **alpha_sign = +1**.
  시작 시 raw 2052(영점보다 +25)로 진자가 약간 흔들리던 상태였지만, 펄스 중 감소폭 71카운트가 잔여 진동(최대 ~25)보다 훨씬 큼.
  **교차 확인(2026-11-18 17:07, `pi_host/logs/auto_sign_iq-60_20261118_170717.csv`, 진자 정지 상태 RAW 2025에서 시작)**:
  iq −60 → Δ0x92 −23.77°, Δ0xA1 −24°, ∫속도 −23.0°; α는 단조 증가(2025→2122, 200 ms) 후 반전 → **alpha_sign = +1 확정**.
  같은 크기 펄스인데 −방향이 더 많이 움직임(+18.6°/145 dps 대 −23.8°/184 dps): 마찰·코깅의 방향 또는 위치 의존 가능 → 실험 2에서 양방향으로 볼 것.
  두 시험 모두 송신 300 ms 중단 직후 0x9C, 0x78 직후 0x9A 응답이 1회씩 없음(재현됨). 원인 미확인.
- 0x77 후 0x9A 브레이크 바이트가 01이 되기까지 1.87 s 걸림(그 전 100~500 ms 동안은 00). 해제 후 기다렸다가 토크를 낼 것.

  → 통신 끊김 보호가 동작해 브레이크를 잠근 것으로 보임. 다만 iq 0 상태에서 본 것이라 0이 아닌 토크 차단은 미확인.
  이 직후 0x9C 1회, 잠금 후 0x9A 1회 응답 없음(30 ms 제한) — 보호 동작 직후 응답 누락 가능, 원인 미확인.

  없는 ID 0x142에는 응답이 없어 Pi 쪽 문제가 아님을 확인. session.py preflight가 이 상태를 감지해 중단한다.

  0x78을 보내면 모터가 마지막 응답만 반복하는 상태가 된다.** 근거: 두 부호 시험 모두 0xB3 보호가 먼저 브레이크를 잠근 뒤
  0x81/0x78 다음 응답이 사라졌고, 실험 1 시작 때 잠긴 상태에서 0x78을 보내자 즉시 발생. 이 상태에서는 피드백이 낡은 값이고

  송신 전 수신 버퍼를 비운다. exp1은 이미 잠겨 있으면 0x78을 보내지 않는다.

  → 종료 절차는 바꾸지 않음. 다시 보면 두 부호 시험 모두 **iq 0(0xA1) 뒤 300 ms 송신 중단으로 0xB3 보호가 작동한 직후 첫 명령(0x9C)부터**
  자기 응답이 사라졌고, 당시 preflight는 0x92만 봐서 반복된 낡은 0x92를 정상으로 착각함.
  **새 후보(미검증): 토크 모드(0xA1)에서 0xB3 보호가 작동한 뒤 응답이 꼬인다.** 읽기 명령만 보낸 뒤 수 초 쉬는 것은 문제없었음.
  당분간 토크 시험은 일부러 보호를 작동시키지 말고(송신 중단 시험 제외) 0x81 → 0x78로 끝낼 것.
- **2026-11-18 17:22 0xB3 = 0(꺼짐)으로 되돌림**(응답 `b3 00 …`, 이후 0x9A/0x92/0x9C 정상). 반복 상태가 두 번 모두 토크 후 보호 작동 직후
  시작돼서 의심 원인을 끈 것. 이후 스크립트에서 0xB3 쓰기와 "송신 중단으로 보호 작동시키기" 단계를 모두 뺐다.
- 응답 반복 상태 복구: 짧은 재투입으로는 안 풀릴 수 있음. 48 V를 끄고 **30 s 이상**(LED 완전 소등) 뒤 재투입하니 정상.
  모터를 끈 채 송신하면 ACK가 없어 can0이 ERROR-PASSIVE가 되며, 재투입 후 읽기 명령 30회 정도로 ERROR-ACTIVE 복귀.
- **0x92 다회전 카운트는 모터 전원 재투입 시 초기화**되고 한 바퀴 안 각도만 유지됨(816.33° → 96.33°, 정확히 −2바퀴).
  세션 간 바퀴 비교는 전원 재투입 여부를 함께 봐야 한다.
- 왕복 지연(0xA1 송신→응답): 평균 0.42 ms, 최대 0.57 ms.
- 정지 마찰: 진자 단 상태에서 0.25~0.30 A부터 팔이 움직임. 토크 0이면 약 1 프레임 안에 멈춤(마찰 지배).
- 토크상수: 데이터시트 Kt 2.1 N·m/A(정격 9.5 A→20 N·m, 피크 29.1 A→60 N·m과 일치)를 초기값으로.
  성능 차트(MT2412240003)의 I는 **입력 직류 전류**(Pin = U×I)라 그 기울기 2.65는 iq 토크상수가 아님.

- **관성이 시뮬보다 10~20배 클 가능성**: auto_sign_test(iq 60, 0.2 s)에서 가속도 ≈11.8 rad/s², 평균 iq 0.56 A
  → J ≈ 0.05~0.10 kg·m²(마찰 0.28 A 차감~무시). 첫 번째 실험의 iq 40/50 펄스 J 0.056~0.071과도 일치.
  시뮬 학습 조건 armature 5e-3. Kt가 2.1보다 작아도 같은 모습이므로 **실험 2에서 관성·마찰·Kt를 함께 맞춰 확정**.

## Pi 실행 도구 (pi_host/)
- `policy_np.py` + `actor_rev11.npz`: numpy 추론, SB3와 최대 3e-6 차이.
- `check_hw.py`(토크 없는 확인), `canguard.py`(can0 점검), `auto_sign_test.py`(부호 자동 판정, 모터 사용).
- **스윙업 실행 요청 = 기본 명령 `python3 pi_host/run_policy.py --run --tau 1.0 --comp --iq-max 120 --seconds 10`** (2026-11-20 기본 동작 변경, 백업 `run_policy.py.bak_20261120e`):
  측정값 자동 재사용·재측정 — `pi_host/logs/kit_params_latest.json` 이 valid·30분 이내·현재 모터 온도 ±3°C 면 그 bridge Fc±·b 로 펄스 생략,
  아니면 kit_identify 와 같은 펄스로 재측정해 바로 실행하고, 정책이 끝난 뒤 .venv quick_id 로 MuJoCo 용 J·Fc±·b 까지 계산해 `kit_params_<시각>.json`·`kit_params_latest.json` 저장.
  어느 쪽을 썼는지·이유는 시작 때 출력, `_fric.json` 의 `fric_info` 에 기록. **제동 제한 기본 켬(5 W, 직립 ±20° 밖)**.
