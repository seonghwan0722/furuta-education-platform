# 제어실험실의 Pi 실물 실행

2026-11-26. 현재 소스의 기능이며, 기존 `dist-ux` 설치 파일은 다시 빌드하지 않았다.

## 구현된 흐름과 남은 확인

앱에서 PID·LQR·LMPC와 파라미터를 선택하면, 수치 설정을 USB로 전송하고 Pi가 센서 상태에서 직접 명령을 계산한다. PC가 매 주기 토크를 보내는 방식이 아니다. 제어 주기는 기존 50 Hz이며 기존 강화학습 정책 경로와 같은 모터 구동 함수를 사용한다.

사용자가 요청한 시작 방식은 **아래 자세 → 자동 에너지 스윙업 → 선택한 PID·LQR·LMPC로 균형 유지**다. 전환 순간의 팔 위치를 기준점으로 삼는다. 스윙업 구간에서 신경망 정책을 대신 실행하지 않는다.

**코드 작성과 소스 검토만 완료했다.** 이번 작업에서 앱·자동 테스트·시뮬레이션·Pi 설치·모터를 실행하지 않았다. 현재 게인과 스윙업 후보의 실물 성공 여부, Python과 JavaScript의 수치 일치, Pi의 LMPC 계산 시간은 미확인이다. 과거 MATLAB 또는 SAC 성공 기록을 이번 경로의 성공 근거로 사용하지 않는다.

## 여는 곳

```powershell
cd C:\Capstone1\furuta-pendulum-rl\app
npm.cmd start
```

1. 상단 **제어 실험실**을 열고 PID / LQR / LMPC를 고른다. 연결된 Pi를 분리할 필요는 없다. 다른 실행은 끝나 있어야 한다.
2. **시뮬레이션**에서 직립 근처 실험 또는 아래에서 자동 스윙업하는 실험을 선택한다. 아래 시작은 현재 보정 비선형 모델을 사용한다. 시뮬레이션 결과 자체가 실물 안정성을 보증하지는 않는다.
3. **실제 키트**를 선택한다. **키트 연결하기**에서 포트를 고르고 **키트 점검**으로 응답을 확인한다. `control1` 기능을 알리지 않는 구버전 수신기는 시작을 허용하지 않는다.
4. 진자를 아래로 내려 두고 사용자가 **실제 키트 시작**을 누른다. 시작 이후의 수평 측정부터 팔이 움직인다.
5. 준비가 끝나면 스윙업과 균형 유지를 합쳐 **10초** 실행한다. 준비 시간은 10초에 포함하지 않는다.
6. **정지**는 준비·스윙업·균형 유지 중 모두 요청할 수 있다. 화면은 Pi의 종료 응답을 기다린다. 전송 중 취소했다면 전송 종료 후 실행 명령을 보내지 않는다.

실물의 PID→LQR→LMPC 자동 연속 실행은 제공하지 않는다. 각 실험의 종료 상태를 확인하고 사용자가 다음 방법을 직접 시작한다. 실행 중에는 설정 변경과 제어실험실 닫기를 막는다. 연결만 하거나 설정을 업로드하는 동작은 모터를 구동하지 않는다.

## Pi에 필요한 파일

[USB_SETUP.md](USB_SETUP.md)의 기존 설치 순서에 따라 아래 파일을 함께 둔다.

- `kit_server.py`
- `kit_cal.py`
- `classical_control.py`
- `setup_usb_serial.py`

현재 Pi의 `pi_host`와 `run_policy.py`, `session.py`, `canguard.py`를 재사용한다. 오래된 PC 사본으로 덮어쓰지 않는다. Python 의존성은 기존 `numpy`, `python-can`, `smbus2`를 사용하며 SciPy·CVXPY를 새로 요구하지 않는다. 설치 도구는 이 파일들과 서비스 계정 접근 권한을 조회한다.

설치 도구의 서비스에는 작은 행렬 계산의 스레드 과다 생성을 줄이도록 BLAS/OMP 스레드 수 1 설정을 넣었다. 이는 실시간 실행 보장이 아니다. 실제 설치·재시작은 아직 하지 않았다.

## 실제 실행 단계

| 단계 | 동작 |
|---|---|
| 설정 확인 | 전체 JSON 크기·CRC·필드·유한 값·단위·행렬 검사. LMPC 예측 행렬 사전 계산 |
| 시작 점검 | 기존 CAN·센서·다른 송신자 점검, 아래 정지 자세 대기 |
| 수평 측정 | 기존 브레이크 해제·0.6 A 펄스 측정, 영점 식·기울기 검사 |
| 스윙업 | 현재 rev11 모델의 에너지/역동역학 후보로 아래 자세에서 올림 |
| 전환 | 직립 오차 ≤ 5°, 진자 속도 ≤ 0.2 rad/s, 팔 속도 ≤ 4 rad/s를 모두 만족하면 선택 제어기로 전환 |
| 직립 유지 | 팔 기준점 포착, PID 누적 또는 LMPC 이전 계획 초기화 후 실행 |
| 종료 | 시간 만료·사용자 정지·오류 시 기존 `graceful_stop`; 완료 응답 후 기록 저장 |

전환 조건은 **현재 모델 후보의 시작 조건**이며 검증된 안정 영역이 아니다. 이전 MATLAB에서 사용한 13° 성공 영역과 같은 결과로 해석하지 않는다. 균형 유지 중 직립 오차 60°를 벗어나면 종료하며 자동 재스윙업은 하지 않는다. 정해진 시간 안에 전환하지 못하면 `nocapture`로 기록한다. 마지막 순간에 포착했다가 시간이 끝나는 것도 충분한 유지 성공을 뜻하지 않으므로 유지 구간 길이를 함께 확인한다.

설정한 힘의 상한은 스윙업·직립 제어 출력에 적용된다. 준비 단계의 수평 측정과 종료 절차는 기존 구동 설정을 사용한다. 실물의 시작각·외란을 화면 값으로 강제 이동시키지 않으며, 시뮬레이션 재생 배속을 Pi에 적용하지 않는다.

## 제어기와 단위

- 상태는 `[전환 기준 팔 각도, 직립 오차, 팔 속도, 진자 속도]`, 단위는 rad·rad/s다. 기존 센서의 진자 각도는 아래가 0, 직립이 ±π다.
- PID는 진자 오차 P·I·D와 팔 위치·속도 피드백이다. 기준 LQR에서 얻은 P·D 기준에 수업 화면의 배율을 적용한다. 기존 누적 제한을 유지한다.
- LQR은 앱 모델의 직립 선형화와 Q·R로 계산한 K를 전송한다. 실제 제어는 Pi가 `u=-Kx`로 수행한다.
- LMPC는 A·B·Q·R·종단 P·예측 길이를 전송한다. Pi에서 입력 제한 QP를 매 주기 계산하고 첫 입력만 적용한다. 각도·속도는 QP 내부 제약이 아니다.
- 정규화 명령 1은 2.52 N·m 기준이다. 기존 전류 상한 1.2 A, 팔 1100°/s, 진자 25 rad/s, 속도에 따른 토크 제한, 제동 제한과 0.01 A 양자화를 유지한다.
- LMPC 미수렴, 비유한 계산, 계산 예산 초과 시 근사 입력을 계속 보내지 않고 종료한다. 계산 예산 10 ms는 계산 시간 감시이며, 플랜트나 센서 경로에 추가한 지연이 아니다. 네이티브 선형대수 호출이 길어지면 반환 후에 시간 초과를 감지할 수 있다.

## 스윙업 후보의 출처

로컬 `C:\Capstone1\furuta_platform\swingup.py`의 `EnergyTeacher` 구조와 `tools/train_swingup.py`의 초기 게인을 참고했다. 현재 앱 `assets/model.js`의 rev11 질량행렬·중력·마찰·토크 배율로 다시 구성했다. 이전 모델의 관성·마찰이나 1.5 A 조건을 복사하지 않았다.

아래 영점 α에서 진자 에너지는 `E = 0.5 M11 αdot² + g2(1−cosα)`, 목표는 `2g2`다. 팔 가속도가 진자 에너지에 주는 입력 항 `−M01 αdot θddot`의 부호를 사용해 가속도를 정하고, 모델 역동역학으로 토크를 계산한다. 시작 후보는 에너지 게인 7000, 속도 감쇠 1.5, 정지 기동 가속도 35 rad/s²이며 슬립링 구성에 맞춰 팔 위치 복귀 항은 0이다. 현재 공칭 마찰 보상은 이 스윙업 계산 내부에만 포함된다. 최종 토크는 기존 구동 제한을 거친다.

모델 오차·전류 제한·제동 제한으로 에너지 증가가 보장되는 것은 아니다. 이 값으로 포착·균형 유지가 성공했다고 보고하지 않는다.

## 기록을 읽는 방법

Pi에는 `logs/kit_control_<방법>_<시각>.csv`와 `.json`이 생성된다. 제어기 설정과 CRC, 스윙업/직립 단계, 포착 시각·팔 기준점, 요청 입력·전류 명령, 센서 상태, 계산 시간과 QP 잔차, 종료 사유를 남긴다. `command_status`는 시도한 명령의 응답 여부를 구분하며, 토크 명령값을 실제 측정 토크로 해석하지 않는다.

USB 상태 `T`는 50 Hz, 추가 진단 `V`는 약 10 Hz와 단계 변경 시 전달한다. 앱 CSV에서 수신하지 못한 진단값은 빈칸이다. 상한 도달 비율은 수신한 진단 표본 기준이며 Pi 전체 기록과 표본 수가 다를 수 있다.

화면의 전체 평균 오차는 스윙업을 포함한다. 직립 제어 구간 평균은 따로 표시한다. 전환 시 팔 기준점이 바뀌므로 상대 팔 각도 그래프에는 기준 변경이 나타날 수 있다. Pi의 `theta_run`은 실행 시작부터 연속된 각도이고, `theta`와 `arm_reference_deg`는 현재 제어 기준을 설명한다.

## 현재 실물 연결의 전제

PC USB 케이블 하나로 Pi 전원까지 공급하는 구성의 PC 출력 사양은 아직 확인되지 않았다. Pi SSH 조회도 인증 거절 상태여서 이번 코드를 설치하지 못했다. 케이블을 빼면 Pi도 꺼질 수 있으므로 소프트웨어 heartbeat 정지가 실행되지 않는다. 모터 자체 통신 두절 차단은 별도 확인 대상이다. USB 분리를 정지 방법으로 사용하지 않는다.
