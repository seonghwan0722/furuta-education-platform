# 연결 직후 MPU-9250 수평 안내

MPU-9250을 **움직이지 않는 받침(베이스)** 에 고정하면, 키트 연결 창에서 앞뒤·좌우 기울기와 전체 기울기를 계속 확인하며 받침을 조정할 수 있습니다. 회전하는 팔이나 진자에 붙이면 베이스의 수평을 측정할 수 없습니다.

이 기능은 모터를 움직이지 않습니다. 기존 ‘키트 맞추기’와 실행 전 팔을 돌려 측정하는 `M level`은 별도 기능이며 그대로 유지합니다. IMU 값이 모터 명령·정책 관측·기존 5° 종료 기준을 바꾸지 않습니다.

## 설치 방향과 각도의 뜻

- 수평인 받침에서 센서의 **+Z가 위쪽**, +X가 장치 앞쪽, +Y가 왼쪽을 향하도록 고정합니다. 센서 PCB의 표시 방향을 확인하세요.
- 기본값 `--imu-axes x,y,z`는 센서 X/Y/Z를 베이스 X/Y/Z로 그대로 사용합니다. 수평면에서 90° 돌려 장착했다면 실제 방향에 맞춰 `--imu-axes y,-x,z` 등의 올바른 회전 대응을 지정합니다.
- 기울어진 현재 자세를 자동으로 0°로 저장하지 않습니다. 센서와 받침 사이의 기계적 장착 오차는 실제 수평자 등으로 확인하고 장착을 바로잡습니다.
- 좌우(roll)는 `atan2(ay, az)`, 앞뒤(pitch)는 `atan2(-ax, √(ay²+az²))`입니다. 위 좌표에서 roll 양수는 왼쪽이 높음, pitch 양수는 앞쪽이 낮음입니다.
- 전체 기울기는 `atan2(√(ax²+ay²), az)`입니다. 두 축을 따로 만족하는 것과 전체 기울기가 목표 이내인 것은 다릅니다. 센서를 뒤집으면 전체 기울기는 180° 부근이므로 수평으로 표시하지 않습니다.
- 앱의 기본 **전체 기울기 1° 이내**는 조정 목표입니다. 보증된 센서 정확도나 실물 제어 성공 경계가 아닙니다. 실제 수평자와 비교해 장착·센서 바이어스를 확인하세요.

## 배선

현재 물리 핀 **1·3·5·6이 이미 사용 중**이므로 비어 있는 핀처럼 꽂도록 안내하지 않습니다. 기존 장치가 I2C1을 사용한다면 주소가 다른 센서끼리 SDA/SCL을 공유할 수 있습니다. CAN HAT의 스택 헤더·분기 단자에서 해당 신호가 그대로 연결되는지 확인하고 전원을 끈 상태에서 배선합니다.

| MPU-9250 모듈 신호 | Pi 신호 | 물리 핀 기준 |
|---|---|---|
| 3.3 V 공급 입력 | 3V3 | 1 또는 17의 같은 3.3 V 전원 계통. 모듈의 공급 사양 확인 |
| GND | 공통 GND | 예: 6 또는 9. 기존 접지를 공유 |
| SDA | GPIO2 / I2C1 SDA | 3. 기존 I2C 배선에 분기 |
| SCL | GPIO3 / I2C1 SCL | 5. 기존 I2C 배선에 분기 |
| AD0 | 모듈의 주소 선택 | Low: 0x68, High: 0x69. 모듈 회로 확인 |

Pi의 I2C 논리는 3.3 V입니다. SDA/SCL을 5 V로 끌어올리는 모듈 배선을 사용하지 않습니다. 기존 AS5600이 기본 주소 0x36이라면 MPU의 0x68/0x69와 주소가 겹치지 않습니다. 실제 HAT의 핀 사용, 풀업과 배선을 확인하세요. 다른 I2C 버스를 이미 구성했다면 그 번호를 `--imu-bus`에 지정합니다. 이 옵션이 GPIO 배치나 운영체제 I2C 설정을 자동 변경하지는 않습니다.

## Pi 프로그램 반영

1. 변경된 `kit_server.py`와 새 `mpu9250.py`를 같은 `kit` 폴더에 복사합니다. 나머지 기존 Pi 호스트 파일과 서비스 경로를 유지합니다.
2. Raspberry Pi 설정에서 사용하는 I2C 버스를 활성화하고, 서비스를 실행하는 계정에 해당 `/dev/i2c-N` 접근 권한을 부여합니다. 서비스 계정의 `i2c` 그룹 변경은 새 로그인/서비스 재시작 후 적용됩니다.
3. 서비스가 사용하는 Python에 `smbus2` 또는 시스템 패키지 `python3-smbus`가 있어야 합니다. 가상환경이면 해당 환경에 설치합니다. 드라이버는 `smbus2`를 먼저 사용하고 없으면 `smbus`를 사용합니다.
4. 기존 서비스의 실행 명령에 필요할 때만 아래 옵션을 추가한 뒤, 모터 실험이 끝난 상태에서 수신기를 재시작합니다.

```text
--imu-bus 1 --imu-address 0x68 --imu-axes x,y,z
```

예시(직접 실행 방식이며 이미 실행 중인 서비스와 동시에 띄우지 않음):

```bash
python3 kit/kit_server.py --serial /dev/ttyGS0 --host-dir pi_host --imu-bus 1 --imu-address 0x68 --imu-axes x,y,z
```

연결 응답은 `I ... v2 ... imu1`입니다. `imu1`은 수신기가 IMU 조회 규약을 지원한다는 뜻이며, 센서 연결 성공을 뜻하지 않습니다. 센서가 없어도 USB 연결은 유지하고 ‘측정 불가’를 표시합니다.

## 측정 상태와 동작

- 앱은 대기 중 약 5 Hz로 `U <요청번호>`를 보냅니다. 수신기는 해당 시점의 가속도·각속도 레지스터를 읽어 답합니다. 모터 CAN 코드는 호출하지 않습니다.
- ±2 g / ±250°/s, 하드웨어 저역 필터를 사용합니다. 자력계·방위각은 수평 판단에 사용하지 않습니다.
- 가속도 크기가 1 g에서 0.08 g 이내이고 자이로 크기가 3°/s 이내이며 가속도 벡터 변화가 작을 때 정지 후보로 봅니다. 최소 4개 표본·0.6초 후 `ok`를 보냅니다. 앱은 추가 안정 시간과 목표 각도를 판단합니다.
- 조정 중에는 `moving` 상태로 각도를 계속 보여 줍니다. 이때 가속도가 중력만을 나타내지 않을 수 있어 수평 완료 판정에 사용하지 않습니다.
- 읽기 오류·잘못된 센서 ID·새 데이터 없음은 `unavailable`이며 이전 각도나 0°로 대체하지 않습니다. 통신 오류 후에는 3초 간격으로 재연결을 시도합니다.
- 정책 전송, 모터 실행, 키트 맞추기 중에는 IMU 조회를 쉬며, 이미 전송된 조회가 도착하면 `paused`로 답합니다. 제어 중 I2C 수평 조회를 끼워 넣지 않습니다.
- 실행·연결 공백 후에는 안정 판정을 다시 시작합니다. 앱에서 응답이 오래되거나 연결이 끊기면 최근 수평 완료 표시를 유지하지 않습니다.

## 모터 없이 확인

```bash
python3 -m unittest discover -s kit -p test_mpu9250.py -v
python3 kit/test_imu_tcp.py --host-dir pi_host
python3 kit/kit_server.py --tcp 127.0.0.1:47800 --fake --fake-tilt-deg 2 --fake-tilt-dir 90
```

가상 장치는 `fake:true`를 명시합니다. 이 검증은 실제 MPU의 배선·장착 오차·센서 바이어스 검증을 대신하지 않습니다. 실물에서는 수평자와 비교하고 한 방향씩 받침을 기울여 표시 방향과 값을 확인해야 합니다.

`test_imu_tcp.py`는 별도 가상 수신기 프로세스를 띄워 연결·연속 각도·요청번호·업로드 중 일시 정지·가상 키트 맞추기 중 일시 정지와 정지 요청·재연결을 확인합니다. 대기 중 `U`가 가상 모터나 AS5600 생성자조차 호출하지 않는지도 확인합니다. 이 시험 역시 물리 장치를 열지 않습니다.
