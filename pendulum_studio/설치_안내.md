# Pendulum Studio Classroom 설치 안내

**소스 버전 0.3.0-classroom.2 · 2026-11-26**

회전 도립 진자로 강화학습과 PID·LQR·LMPC를 배우는 Windows 데스크톱 앱입니다. 이 안내는 `furuta-education-platform` 저장소의 `pendulum_studio/` 통합 사본을 기준으로 합니다. 원본과 변경 범위는 [README](README.md)를 참고하세요.

**최신 기능은 현재 소스에 반영되어 있습니다.** 원본 저장소의 [기존 v0.2.0 릴리스](https://github.com/sjh030619-boop/furuta-pendulum-rl/releases/tag/v0.2.0)에는 이후 추가한 활동 0, 현재 `.pendulum` 저장 형식, 제어 실험실과 새 USB·실물 고전제어 연동 변경이 들어 있지 않습니다. 최신 설치 파일을 새로 배포한 상태로 오해하지 않도록, 우선 아래 소스 실행 또는 직접 빌드 절차를 이용하세요.

## 1. 현재 소스로 실행하기

Windows에 Node.js와 npm을 준비한 뒤, 통합 저장소를 내려받은 폴더에서 PowerShell을 엽니다.

```powershell
cd pendulum_studio
npm.cmd install
npm.cmd start
```

- 이미 `pendulum_studio` 폴더에서 PowerShell을 열었다면 `cd` 줄은 생략합니다.
- `npm.cmd`는 PowerShell에서 `npm.ps1` 실행 정책 오류를 피하기 위한 명령입니다. 시스템 실행 정책을 변경할 필요가 없습니다.
- 소스를 갱신했다면 앱을 완전히 종료하고 `npm.cmd start`로 다시 실행합니다.
- PC 시뮬레이션에 필요한 모델·정책은 `src/assets/`에 포함되어 있습니다. Python, Raspberry Pi, 원본의 `s2r/`·`rl/` 폴더는 PC 앱 실행에 필요하지 않습니다.
- 설치 중 Electron 바이너리 또는 `serialport` 설치 오류가 있으면 설치 로그를 확인합니다. `serialport`가 없어도 PC 시뮬레이션은 열릴 수 있지만 실제 키트 직렬 연결은 사용할 수 없습니다.

## 2. 다른 PC에 전달할 설치 파일 만들기

의존성을 설치한 `pendulum_studio` 폴더에서 실행합니다.

```powershell
npm.cmd run dist
```

빌드 성공 시 현재 설정의 출력 파일은 다음과 같습니다.

```text
pendulum_studio/dist/PendulumStudio-Classroom-Setup-0.3.0-classroom.2.exe
```

이 파일로 설치하는 PC에는 Node.js·Python이 필요하지 않습니다. 설치 창에서 위치와 바로가기를 선택하며, 앱 이름은 **Pendulum Studio Classroom**입니다. 사용자 계정 단위로 설치하도록 설정되어 있지만 학교 PC의 보안 정책은 별도로 적용됩니다. 코드 서명 설정은 포함되어 있지 않으므로 게시자와 전달받은 파일의 출처를 확인하세요.

**이 안내 작성 과정에서는 최신 설치 파일 빌드·설치·앱 실행 시험을 하지 않았습니다.** 생성한 설치 파일은 배포 전에 담당자가 직접 확인해야 합니다. 기존 Pendulum Studio와의 덮어쓰기 설치도 확인하지 않았습니다.

Pi 수신기와 USB 설정은 Windows 설치 파일에 포함되지 않습니다. 실제 키트는 별도 준비가 필요합니다.

## 3. 수업 화면 사용하기

| 여는 곳 | 할 수 있는 일 |
|---|---|
| 활동 0 · 배경지식 | 학습 방식 비교, 길찾기·밴딧·할인 보상 체험, 진자와 수학적 모델링 이해 |
| 활동 1 · 살펴보기 | 지도·비지도·강화학습, 한 번의 경험, 강화학습의 분류를 진자 실험과 연결 |
| 활동 2 · 점수 규칙 만들기 | 블록으로 보상을 정하고 규칙 점검과 예시 규칙 활용 |
| 활동 3 · 가르치고 시험하기 | 학습 조건을 바꾸고 시뮬레이션·그래프로 결과 비교 |
| 상단 · 제어 실험실 | PID·LQR·LMPC 설명, 설정, 그래프, 실험 노트 |
| 상단 · 도움말 | 활동 순서, 저장 범위, 예제와 키트 사용 안내 |

**따라 하기**는 미리 SAC로 학습한 아홉 가지 정책을 선택합니다. **자유롭게 만들기**는 미리 배운 정책에서 출발해 학생의 점수 규칙에 맞게 CEM으로 고쳐 배웁니다. PC 앱이 PPO·SAC를 처음부터 학습시키는 방식은 아닙니다. 실제 키트에서는 Pi가 전달받은 정책을 추론합니다.

학습·시험 결과는 기록 표와 그래프에서 비교할 수 있습니다. 키트 없이 먼저 시뮬레이션과 배경지식 예제를 이용할 수 있습니다.

## 4. 수업 파일 저장하기

상단 **저장하기**로 `.pendulum` 파일을 만들고, 다음 수업에는 앱 안의 **불러오기**로 엽니다. 자동 저장이나 더블클릭 파일 연결을 전제로 하지 않습니다.

- 포함: 활동 1~3의 작품 이름·블록·조건·배치, 현재 정책 한 개, 최근 8개 기록과 그래프, 활동 진행 상태.
- 제외: 활동 0 체험 기록, 제어 실험실 기록, 키트 포트·보정값·구동 승인, 학습 중간 상태.
- 제어 실험실의 실험 기록은 CSV, 학습 노트는 JSON으로 따로 내보냅니다.
- 이전 v2 `.json` 작품도 읽을 수 있지만, 원래 파일에 없던 정책·결과 기록은 복원되지 않습니다.
- 저장된 성공 결과를 열어도 실물 실행 승인이 복원되지는 않습니다. 파일을 여는 것만으로 모터가 움직이지 않습니다.

자세한 범위는 [수업 프로젝트 파일 안내](design/PROJECT_FILES.md)를 참고하세요.

## 5. 실제 키트 연결 상태와 준비

현재 선택한 방식은 **PC USB 데이터 케이블 → Raspberry Pi 5 USB-C**, 같은 케이블로 Pi 전원도 공급하는 구성입니다. **PC 전원 출력, Pi 설치, USB 실물 통신은 아직 확인하지 않았습니다.** 연결 설정과 확인할 항목은 [USB_SETUP.md](kit/USB_SETUP.md)를 따릅니다.

Pi에는 `kit_server.py`와 별도 모터·센서 백엔드가 필요합니다. 이 통합 저장소에는 `teammate/rev11_s2r_calib/pi_host/`가 있으며, 실제 Pi에 이미 설치된 최신 백엔드 폴더를 `--host-dir`로 지정합니다. `kit_server.py`의 기본 `../pi_host`는 현재 통합 폴더 구조와 다릅니다. 기존 Pi 파일을 통째로 덮어쓰는 절차가 아닙니다.

- 강화학습 경로: 앱에서 정책을 전달하고, Pi가 50 Hz로 추론·구동하며 상태를 앱으로 보냅니다. 기존 SSH 연결을 통한 실행 기록은 [kit/README.md](kit/README.md)에 있습니다.
- 제어 실험실 경로: 아래 자세에서 자동 스윙업 후 선택한 PID·LQR·LMPC로 전환하도록 소스를 추가했습니다. 새 수신기가 필요하며 **실물에서 성공한 결과는 아직 없습니다.** [CLASSICAL_CONTROL.md](kit/CLASSICAL_CONTROL.md)
- 수평 측정·키트 맞추기 또한 새 USB 구성의 실물 검증이 끝난 기능으로 취급하지 않습니다. 시작 버튼을 누르면 팔이 움직일 수 있으므로 담당자가 키트 옆에서 진행합니다.
- 소프트웨어 통신 두절 정지는 Pi가 켜져 있을 때만 실행됩니다. USB 케이블이 Pi 전원도 공급한다면 케이블 분리로 Pi까지 꺼질 수 있습니다. 모터 자체의 통신 두절 차단은 별도 확인 대상입니다.

실제 장치 설정이나 구동을 소스 설치와 동시에 자동으로 수행하지 않습니다.

## 기타

- 화면 글꼴은 외부에서 내려받습니다. 인터넷이 없으면 기본 글꼴로 표시됩니다.
- 자동 업데이트는 없습니다. 소스 또는 확인된 새 설치 파일로 갱신합니다.
- 설치본 삭제는 Windows 설정 → 앱 → 설치된 앱 → Pendulum Studio Classroom → 제거에서 합니다. 별도 저장한 `.pendulum` 파일은 유지됩니다.
