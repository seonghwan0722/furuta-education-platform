# 제어 실험실 UI·UX — 강화학습 화면과 통일

## 설계 기준

`src/css/app.css`와 활동 0 화면의 시각 체계를 따른다. 파란 상단 메뉴, 번호가 있는 활동 안내, 왼쪽의 실행 화면, 오른쪽의 탭 작업대가 하나의 앱으로 읽히도록 구성한다. 제어 계산과 입력 범위는 기존 값을 유지한다.

## 화면 구성

1. **상단 메뉴(48px)**: 기존 Pendulum Studio 로고와 파랑 `#3b6de4`. PID / LQR / LMPC는 짧은 분할 버튼으로 선택한다. 강화학습 화면으로 돌아가는 버튼을 유지한다.
2. **활동 순서(40px)**: 살펴보기 → 조건 바꾸기 → 실험하고 비교하기 → 설명하기. 클릭하면 해당 오른쪽 탭을 연다. 현재 단계는 흰 배경과 파란 테두리로 표시한다.
3. **왼쪽 진자 화면**: 진자와 회전 팔의 두 뷰, 현재 표시된 실험의 방법·조건·시간. 840×440 캔버스에서 제목과 수치를 크게 표시한다.
4. **왼쪽 실행 영역**: 진자 바로 아래 시작하기 / 정지하기 / 재생 속도. 바로 아래의 ‘다음 실험’에는 편집 중인 조건을 표시하며 ‘조건 변경’으로 설정 탭을 연다.
5. **왼쪽 결과 영역**: 진행바, 평균 기울기 오차, 모터 힘 RMS, 힘 상한 도달 비율 및 실행 상태. 오른쪽을 스크롤해도 진자와 정지 버튼을 계속 볼 수 있다.
6. **오른쪽 살펴보기**: 강화학습과의 연결 설명, 선택한 방법의 원리, 상태 → 제어 규칙 → 행동 → 다시 관찰하는 흐름, 예상·관찰·설명 안내. 수식과 상세 조건은 접힌 영역으로 유지한다.
7. **오른쪽 설정**: 기존 게인·중요도·예측 길이와 공통 실험 조건을 옮겼다. 고급 조건은 기존 펼침 영역을 유지한다.
8. **오른쪽 그래프**: 세 방법 비교 버튼, 기울기와 모터 명령, 제어기 내부 항/예측, 최근 실험 기록 및 CSV 받기.
9. **오른쪽 실험 노트**: 실험 과제와 예상·관찰·설명, 확인 질문. 글 입력란은 세로 배치로 읽기와 쓰기 공간을 확보한다.

## 시각 규칙

- 본앱과 같은 Pretendard 폰트(CDN), 미연결 시 맑은 고딕 계열로 대체한다.
- 배경 `#EEF2F5`, 본문 `#14212B`, 보조 글 `#51606E`, 선 `#D7DEE3`.
- 카드 모서리 12px, 입력과 버튼 8px, 오른쪽 탭 높이 34px.
- 상태/제어 규칙/행동/보상 표시는 본앱의 파스텔색과 진한 테두리 배지를 사용한다.
- 본문은 13px, 카드 제목은 16px 중심으로 맞추고 큰 도입 배너와 별도 하단 도크를 제거했다.
- 선택된 탭은 파랑, 성공과 종료 상태는 문구와 함께 구분한다.

## 동적 연결

- `[data-lab-tab="overview|settings|results|notes"]`와 대응 패널의 ID·ARIA 연결을 유지한다. 좌/우/Home/End 키로 탭을 선택한다.
- 모든 `[data-open-tab]` 버튼은 해당 탭을 열고 탭 제목으로 초점을 옮긴다. 활동 순서 안에서는 `aria-current="step"`을 동기화한다.
- 첫 화면은 `overview`이다. 시작하기와 세 방법 비교는 기존대로 `results`를 자동으로 연다.
- `#selectedMethod`, `#methodDescription`, `#resultContext`는 현재 캔버스가 보여주는 실험 기준이다. 이전 실험이 없으면 선택된 방법을 표시한다.
- `#setupSummary`는 다음 실행 조건이다. 이전 결과와 새 설정이 섞이지 않게 별도 위치에서 표시한다.
- 실행 중에는 기존처럼 입력·방법 선택·새 실행을 잠근다. 살펴보기·그래프·노트 탐색과 정지 버튼은 사용할 수 있다.
- `#recordCount`는 긴 문자열을 담으므로 탭에서 실험 기록 섹션 제목으로 옮겼다.
- 기존 input ID, 값·범위·step, data-method / data-preset, localStorage 키와 스크립트 순서를 유지한다.

## 화면 크기와 접근성

- 주 대상은 본앱 최소 크기 1100×720 및 1440×900이다. 왼쪽 고정 영역과 오른쪽 내부 스크롤을 사용한다.
- 폭 1200px 이하에서는 그래프를 세로로 배치하고 왼쪽을 440px로 둔다. 좁은 화면에서는 카드 내부도 한 열로 바꾼다.
- 폭 720px 이하에서는 전체 화면을 한 열 스크롤로 바꾼다. 높이가 짧은 데스크톱에서는 왼쪽도 스크롤할 수 있게 한다.
- 탭/입력/버튼 초점, label, native details/summary, 상태 알림, 가로 스크롤 가능한 기록 표를 유지한다.

## 데이터와 검증 범위

기존 실험은 10초이며 게인·힘 범위·정지 조건·플랜트·Pi 통신은 수정하지 않았다. 시뮬레이션 결과를 실물 검증으로 표현하지 않는다. 기록은 최근 12개를 메모리에 보관하고, 강화학습으로 돌아갈 때 사라질 수 있다는 기존 동작을 명시했다. 노트 글 자동 저장과 CSV/JSON 내보내기를 유지했다.

2026-11-26 변경은 소스와 UI 연결의 코드 검토까지만 수행했다. 사용자 요청에 따라 앱 실행·화면 검증·PC 시뮬레이션·빌드·Pi 실물 실행은 하지 않았다.

## 제어 방식별 설명 보강 — 2026-11-26

살펴보기에 `control-lessons.js`의 방식별 설명과 `control-explainers.js`의 조작 가능한 그림을 추가했다. 이해 흐름은 직관 → 그림 조작 → 실제 제어 순서 → 선택해서 펼치는 수식 → 비교 실험의 관찰점이다. 방식 선택 시 새 설명의 처음으로 스크롤을 돌린다.

- **PID**: 마지막 오차가 같은 세 기록을 바꾸며 현재값·누적 면적·변화율을 구분한다. 기준 게인의 배율, 팔 위치·속도 피드백, 조건부 적분과 출력 포화를 설명한다. 기본 PD가 기준 LQR과 같은 식임을 명시한다.
- **LQR**: 고정된 두 가상 후보에 qφ와 R을 바꾸어 비용을 비교한다. 이 예시는 실제 최적해가 아니며, 실제 LQR은 선형 모델·Q/R에서 K를 계산한다는 차이를 밝힌다. 상태 벡터, 이산 비용, 선형 설계와 비선형 실행, 실행 시 입력 포화를 설명한다.
- **LMPC**: 5칸 입력 계획에서 첫 명령만 적용하고 다음 측정 시점에서 다시 정하는 과정을 보여 준다. 재계획으로 명령이 바뀌는 예와 같은 값이 나오는 예를 포함한다. N과 시간, Q/R, 입력 제약, LQR 종단 비용, QP 수렴 및 별도의 실험 종료 조건을 설명한다.
- **공통 비교표**: 명령 결정 방식, 사용자가 바꾸는 값, 입력 제한 처리와 그래프 관찰점을 나란히 둔다.

설명용 그래프의 숫자는 가상 예시이며 실험 결과로 저장하지 않는다. 해당 버튼과 슬라이더는 제어 계산·플랜트·실험 설정·Pi 통신을 호출하거나 변경하지 않는다. 좁은 화면에서는 개념 카드를 한 열로 두고, 표와 그림만 내부 가로 스크롤을 허용해 글자가 지나치게 축소되지 않도록 한다.

수식과 동작 설명은 `src/js/control-core.js`를 기준으로 읽기 전용 검토했다. 추가로 [MathWorks의 이산 LQR 정의](https://www.mathworks.com/help/control/ref/lti.dlqr.html)와 [MPC 설명](https://www.mathworks.com/help/mpc/gs/what-is-mpc.html)을 대조했다. 이번 보강에서도 앱 실행·화면 검증·실험·빌드는 수행하지 않았다.
