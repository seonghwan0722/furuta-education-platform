# 수업 프로젝트 저장·불러오기

2026-11-26 로컬 확장판의 파일 정의입니다. 상단 메뉴의 저장·불러오기는 **활동 1–3에서 만든 하나의 수업 프로젝트**를 대상으로 합니다.

## 파일 종류

- 확장자: **`.pendulum`** — 예: `힘 아끼기 비교.pendulum`
- 내용: UTF-8 JSON, 식별자 `app: "pendulum-studio"`, 형식 버전 `v: 3`
- 선택 이유: 규칙뿐 아니라 정책과 실험 기록을 함께 담으므로 수업 전체를 뜻하는 전용 확장자를 사용합니다. 일반 JSON 데이터나 학습 모델 압축 파일과 구별하면서, 텍스트로 구조를 확인할 수 있습니다.
- 최대 파일 크기: 8 MiB. 설치 파일·영상·외부 Python 정책 ZIP을 여는 기능은 아닙니다.

## 저장하고 복원하는 정보

| 정보 | 포함 내용 | 복원 결과 |
|---|---|---|
| 작품 | 이름, 저장 시각, 파일 버전 | 작품 이름 복원 |
| 점수 규칙 | 점수 블록, 조건·수치·중첩·연결 | 같은 규칙을 다시 편집 |
| 실행 규칙 | 학습·시험 블록, 세대·집단 크기·변이 크기·시험 시간 | 다음 시작하기에 적용할 조건 복원 |
| 블록 배치 | 시작 묶음과 따로 놓은 블록의 좌표 | 작업 배치 복원, 이전 작품의 되돌리기 이력은 제거 |
| 수업 방식 | 따라 하기/자유롭게 만들기, 빠르기·힘 감점 단계 | 선택 상태 복원 |
| 진행 | 활동 번호·오른쪽 탭, 활동 1 완료·예상 작성 표시 | 이어서 볼 위치 복원 |
| 현재 정책 | 현재 규칙에 대응하는 신경망 가중치·활성화·출력 방식, 규칙 키, 학습 시간 | 같은 정책으로 시뮬레이션 시험 가능 |
| 실험 기록 | 앱 기록 표의 최근 8개, 시뮬레이션/키트 결과 문구, 직립 시간·평균 힘·팔 회전량 | 저장된 결과임을 표시해 비교 |
| 그래프 | 각 기록과 현재 화면의 학습 점수·시간·높이·힘·팔 회전 데이터, 비교 대상으로 선택한 기록 | 그래프와 비교 선택 복원 |
| 모델 호환 정보 | 저장 당시 모델 상수의 서명 문자열, 관측 차원, 정책 규약 | 현재 앱과 맞는지 검사. 앱의 플랜트 값을 파일 값으로 덮어쓰지 않음 |

학습 조건은 실행 블록에 들어 있으므로 별도의 중복 설정값을 만들지 않습니다. 정책을 아직 배우지 않았으면 정책 항목은 비어 있습니다. 저장하는 정책은 **현재 선택된 정책 한 개**이며, 모든 이전 실험의 정책이나 학습기의 중간 세대 상태를 저장하는 체크포인트는 아닙니다.

현재 앱의 기록 표는 같은 정책을 다시 시험할 때 같은 행을 갱신하고, 그래프도 그 행의 최근 시험으로 갱신합니다. 파일은 이 화면의 기록을 그대로 보관합니다. 매 실행의 원시 센서 로그를 누적하는 형식은 아닙니다.

활동 0의 길찾기 Q표·경로·밴딧 기록, 별도 PID/LQR/LMPC 제어 실험실 기록, 키트 연결·포트·보정값, 실행 중 타이머·학습기 내부 상태, 구동 승인 상태는 포함하지 않습니다. 따라서 수업 파일을 열어도 별도 체험 화면의 상태는 복원되지 않습니다.

## 사용 방법

1. 현재 작업을 보관하려면 상단 **저장하기**를 누릅니다. Windows 저장 창에서 이름과 폴더를 선택합니다.
2. 다음 수업에서는 **불러오기**에서 `.pendulum` 파일을 선택합니다. 불러오면 현재 프로젝트를 바꾸므로 보관할 현재 작업은 먼저 저장합니다.
3. 규칙·정책·기록을 확인합니다. 파일을 여는 것만으로 학습이나 모터 실행이 시작되지는 않습니다.
4. 정책이 들어 있는 파일은 **시뮬레이션 → 시작하기**에서 기존 40조건 안전 시험을 다시 수행한 뒤 화면의 시험으로 이어집니다. 37/40 통과 조건과 실제 키트 인터록은 기존 설정을 사용합니다. 저장된 성공 기록은 새로운 구동 승인으로 사용하지 않습니다.

저장·열기 창이 떠 있거나 학습·시험 중일 때는 파일 버튼을 잠급니다. 저장 성공·불러오기 성공·오류는 상단 안내 줄에서 확인할 수 있습니다. 저장 취소 시 파일을 만들지 않습니다. 앱은 같은 폴더에 임시 파일을 완전히 작성한 뒤 교체하여 저장 중 실패로 기존 프로젝트가 잘리는 일을 방지합니다.

브라우저에서 열린 화면에는 데스크톱 파일 창 대신 다운로드·파일 선택을 사용합니다. `.pendulum`을 더블클릭해 앱을 여는 운영체제 파일 연결은 이번 변경에 포함되지 않습니다. 앱 안의 불러오기 버튼을 사용합니다.

## 이전 파일과 오류 처리

- 이전 형식 `app: "pendulum-studio", v: 2`인 `.json` 파일은 블록·이름·수업 방식·감점 단계를 복원합니다. 해당 파일에 없던 정책·기록은 생성하지 않습니다.
- 이후 저장은 v3 `.pendulum`으로 합니다. 원래 `.json` 파일은 그대로 둡니다.
- 파일 크기·식별자·버전·숫자·블록 연결/종류/순환·정책 차원·기록 길이와 시간 순서를 먼저 검사합니다.
- 현재 앱과 모델/관측 규격이 다르거나 저장된 정책과 점수 규칙·학습 조건이 맞지 않으면 거부합니다. 검사 실패 시 현재 프로젝트를 바꾸지 않습니다.
- 알 수 없는 일반 JSON이나 잘못된 확장자를 선택하면 이유를 안내합니다.

## 구현 위치와 확인 범위

- `src/js/project.js`: 버전별 읽기·쓰기와 데이터 검사
- `main.js`, `preload.js`: 운영체제 파일 창과 UTF-8 파일 처리
- `src/js/app.js`: 화면 상태 수집·복원, 저장 정책 재확인
- `src/js/blocks.js`: 프로젝트를 열 때 되돌리기 이력 초기화

사용자 요청에 따라 앱 실행·파일 왕복 시험·모터 시험은 수행하지 않았습니다. 코드 읽기 검토까지 수행했습니다.
