# rev22 모델로 PPO·SAC 재학습 (MATLAB + Python, 2026-11-27~28)

확인 범위: **PC 시뮬레이션만**. rev22 실물·Pi·Simscape fixed MIL에서는 돌리지 않았다.
rev22 플랜트는 이전 스레드 보고서(`rev22_control/REV22_PID_LQR_LMPC_결과.md`)의 값을 그대로 썼다.

> **가정 명시**: rev22 질량·관성은 STEP 형상에 밀도를 가정해 계산한 값이다(진자 39.2 g, 저울로 재지 않음).
> 마찰·암 관성은 11/23 실측(쿨롱 0.785, 점성 0.186, 전기자 0.0250 + J_body), 결합항 γ는 CAD 값 그대로(rev11처럼 ×0.8 보정 안 함).
> MATLAB `rev22_config("hw1123")`와 같은 플랜트다.

## 0. 요약

- **SAC는 MATLAB·Python 둘 다 잘 됐다.** rev11 레시피(sac25_v3_opt = sac24 보상 + 안정화)를 그대로 rev22 플랜트에 돌렸다.
  - Python ck100, MATLAB ck050 모두 경량 배치 10/15/20 ms에서 123/123, MuJoCo 고정 16개 10/20 ms에서 16/16이다.
  - 플랜트 변경 7조건은 거의 43/43이고, 실물형 조건은 39~42/43이다.
- **PPO는 기존 run12 레시피(hold 0.3)로는 실패했다.** MATLAB·Python 둘 다 300회 뒤 엄격 기준 0/16이었다.
  - 넘어지지는 않는다(마지막 10 s 동안 |θ|<10° 16/16). 직립에서 ±1.5° 안의 빠른 떨림(약 4 Hz)이 있어 진자 속도가 0.7 rad/s까지 나와 ±0.5 rad/s 기준을 못 맞춘다.
  - 보상을 SAC와 같은 기본값(hold 3, wUp 0.05, vUp 0.2)으로 바꾸자 **Python은 두 시드 모두 성공**했다(123/123 ×3 지연, MuJoCo 16/16).
  - **MATLAB은 같은 수정판에서도 약했다.** 시드 1은 90회에 잠깐 좋아졌다가(10 ms 114/123, 20 ms 50/123) 다시 나빠졌다. 시드 2는 20 ms에서 끝까지 0이었다.
- **MATLAB과 Python이 갈린 곳은 PPO 학습 결과뿐이다.** 평가 쪽은 같다. MATLAB 정책을 MATLAB `sp_eval2`와 Python 평가기에 각각 넣으면 SAC ck150은 123/121/120으로 완전히 같고, PPO ck090은 114/39/54 대 114/38/50으로 거의 같다. 플랜트·평가는 같고 **PPO 학습기 구현 차이(또는 시드 민감도)** 때문이다. 정확한 원인은 확인 필요.
- **γ 민감도가 가장 중요한 결과다.** 정책은 학습한 γ 근처에서만 20 ms 지연을 견딘다.
  - rev11 정책(γ×0.8 플랜트로 학습)을 rev22에 그대로 쓰면 10 ms는 되지만 20 ms는 무너진다(sac24 3/123).
  - 반대로 rev22 PPO는 실물 γ가 rev11처럼 CAD의 0.8배면 20 ms에서 1~19/43으로 떨어진다.
  - **rev22 SAC는 γ×0.7~1.1에서 20 ms 39~43/43으로 폭이 가장 넓다.** 실물 γ가 아직 확인되지 않았으므로 rev22 실물 첫 시험에는 SAC를 권한다.

## 2. 평가 조건

평가 조건은 rev22 PID·LQR·LMPC 보고서와 같다(시작점, 시드, 플랜트 변경, 실물형 조건 동일).
- 경량 배치: 고정 3개 + 무작위 120개(시드 2001~2003), 지연 10/15/20 ms, 25 s, 엄격 기준(20 s 안에 도달, ±5°·±0.5 rad/s 5 s 유지, 암 15·진자 25 rad/s 미만)
- 플랜트 변경: 43개, 10 ms
- 실물형: 암 정지마찰 +50%, 진자 영점 +1°(20 ms는 −1°), 진자 베어링 쿨롱 1e-3 N·m
- MuJoCo: rev22 관성 XML, γ CAD, 고정 시작 16개(180°~0°)
- **차이 하나**: RL은 지금까지처럼 회생 한도 0.8 J(넘으면 모터 정지)를 켜고 평가했다. 고전 제어기 평가는 한도가 없었다. 그래서 RL은 20 ms를 한도 없이도 따로 돌렸다.
- rev11 행은 rev11 정책을 rev11 식별 플랜트(γ×0.8)에서 같은 조건으로 돌린 것이다. MuJoCo는 rev11 XML, γ×0.8이다.

## 4. γ(결합항) 민감도

rev22 공칭 플랜트에서 γ만 바꿔 43개를 돌렸다. 각 칸은 통과 개수다. rev22 γ×0.8 ≈ 1.80e-4이고, rev11 식별 플랜트 γ는 1.65e-4이다.

해석:
- RL 정책이 20 ms 지연을 견디는 γ 범위는 학습한 γ 주변이다. rev11 sac24는 γ×0.7~0.8(= rev11 학습 γ 근처)에서만 견디고, rev22 PPO는 γ×0.9 이상에서만 견딘다. 학습 때 γ를 랜덤화하지 않았기 때문이다. 도메인 랜덤화 항목에 γ가 없다.
- 고전 제어기는 rev22 γ로 다시 설계하면 γ×0.8·×1.2 모두 43/43이었다(이전 보고서). RL은 이 축에서 고전 제어기보다 약하다.
- rev22 SAC가 범위가 가장 넓다(20 ms에서 ×0.7~1.1). PPO는 ×0.8 아래에서 급격히 떨어진다.
- 실물 γ가 rev11처럼 CAD의 0.8배라면 rev22 PPO는 20 ms에서 쓸 수 없고, SAC는 문제없다.

## 5. MATLAB과 Python이 어긋난 이유

| 비교 | 결과 | 판단 |
|---|---|---|
| 같은 정책을 MATLAB `sp_eval2`와 Python 평가기로 평가 | SAC 123/121/120 = 123/121/120, PPO 114/39/54 ≈ 114/38/50 | 평가·플랜트는 같다 |
| SAC 학습 (같은 레시피) | 둘 다 성공, 학습 곡선도 비슷 | 일치 |
| PPO run12 그대로 | 둘 다 같은 방식으로 실패(직립 떨림) | 일치 |
| PPO 보상 수정판 | Python 2/2 시드 성공, MATLAB 0/2 (시드 1은 90회에 잠깐) | **불일치** |

- PPO 불일치는 γ 때문이 아니다. 두 학습기의 플랜트(γ 포함)는 같다.
- 남는 후보는 학습기 구현 차이다. Python 판은 `sp_ppo2`를 옮긴 것이지만 Adam 세부, 미니배치 순서, log-std 최적화 방식이 완전히 같다는 보장은 없다. 시드 2개로는 시드 운인지도 가를 수 없다. **확인 필요.**
- 11/23 안정성 실험에서도 MATLAB PPO는 20 ms 성능이 학습 중 떨어지는 경향이 있었다(run12 벤치). 이번과 같은 방향이다.
- 학습 결과가 갈린 곳에서도 결과에 영향을 주는 가장 큰 물리 요인은 γ다(4절). rev11 정책이 rev22에서 20 ms에 무너지는 것도 γ 차이로 설명된다.
