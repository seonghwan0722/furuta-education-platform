# rev22 PPO 세우기: 원인, 계획, 결과 (2026-11-28)

확인 범위: **PC 시뮬레이션만**. rev22 플랜트는 STEP 형상 + 밀도 가정값이다(진자 39.2 g, 실측 아님). 앞 보고서 `REV22_PPO_SAC_결과.md`에 이어지는 내용이다.

## 0. 요약

- PPO는 넘어진 것이 아니었다. 서 있지만 직립 중 진자 속도가 0.6~0.9 rad/s까지 튀어서 엄격 기준(±0.5 rad/s를 5 s 연속)을 못 맞춘 것이다.
- 기존 PPO 계보(rev11 run10 정책에서 이어 학습)는 보상, 탐색 잡음, 학습률, γ 랜덤화를 바꿔도 이 튐이 0.5 아래로 내려가지 않았다(9가지 시도).
- **rev22 SAC 정책의 가중치에서 출발해 PPO로 미세조정하면 선다.** SAC 평균 신경망과 PPO actor는 구조가 같아서(5-64-64-1 tanh) 가중치를 그대로 옮길 수 있다.
  - MATLAB PPO(γ 랜덤화 포함, 80회): 경량 배치 10/15/20 ms 모두 123/123, MuJoCo 16/16, γ×0.7~1.2에서 20 ms 모두 43/43.
  - Python PPO(γ 랜덤화 포함, 120회): 123/121/121, MuJoCo 16/16, γ×0.8~1.1에서 20 ms 39~43/43.
- PPO 미세조정은 출발점 SAC보다 실제로 나아졌다. MATLAB 기준 직립 중 진자 속도 튐이 0.28 → 0.16 rad/s(10 ms), 0.39 → 0.19(20 ms)로 줄었고, γ×1.2·20 ms가 6/43 → 43/43이 됐다.
- 한계: 가중치 변화는 0.7% 수준의 미세조정이다. PPO를 오래 돌리면 다시 나빠진다(MATLAB 120회 이후, Python 280회 이후). 그래서 체크포인트를 일찍 골랐다.

### 1-2. 튐의 원인은 암 쿨롱 마찰

직립 근처에서 시작해 15 s 유지시키고 암 쿨롱 마찰만 바꿨다(진자 속도 최대의 중앙값, rad/s).

| 정책 | 쿨롱 ×1.0 (0.785) 10 ms | 쿨롱 ×0.5 10 ms | 엔코더 양자화 끔 10 ms |
|---|---|---|---|
| PPO run12 그대로 ck300 | 0.64 | 0.35 | 0.67 |
| PPO 보상수정 s2 ck200 | 0.58 | 0.32 | 0.59 |
| SAC ck100 | 0.26 | 0.23 | 0.25 |

- 튐은 쿨롱 마찰에 비례한다. 엔코더 양자화와는 무관하다.
- rev22 플랜트의 쿨롱 0.785 N·m은 rev11 식별값 0.40의 약 2배다. 암이 방향을 바꿀 때 마찰 토크가 1.57 N·m(최대 토크 3.15의 절반)만큼 뒤집힌다. rev11에서 온 PPO 정책은 이 충격을 받아내지 못한다.
- 20 ms 지연에서는 여기에 4.5 Hz 떨림이 더해진다. rev22 γ가 rev11 식별값보다 36% 커서 같은 정책의 루프 이득이 그만큼 높아진 결과로 본다(추정).

### 1-3. 보상이 이 튐을 못 본다

같은 정책에 탐색 잡음을 넣어 성공 영역(±5°, ±0.5 rad/s)에 머문 시간 비율을 쟀다.

- 학습 중 탐색 잡음이 만드는 흔들림이 이 차이보다 크다.

## 4. 해석과 한계

- **무엇이 PPO를 세웠나**: 보상이나 하이퍼파라미터가 아니라 출발점이다. rev11에서 온 PPO 정책은 rev22의 큰 쿨롱 마찰과 큰 γ에서 떨리는 버릇이 있고, PPO의 작은 갱신으로는 300~400회 안에 벗어나지 못했다. SAC가 이미 찾은 조용한 정책에서 출발하면 PPO가 그것을 유지하고 조금 더 다듬는다.
- **PPO가 실제로 한 일**: MATLAB ck080은 actor 가중치가 출발점 대비 0.7% 바뀌었고, 무작위 관측에서 출력 차이는 평균 0.026이다. 작지만 효과는 있었다(3-2, 3-3). 정직하게 말하면 "SAC로 찾고 PPO로 다듬은 정책"이다. PPO만으로 처음부터 만든 정책이 아니다.
- **오래 돌리면 나빠진다**: 학습 목표(주기별 보상)와 평가 기준(5 s 연속)이 달라서, 학습이 진행되면 20 ms 성능이 오르내린다. 지금은 일찍 멈춘 체크포인트를 골랐다. 학습률 감쇠(`cfg.lrAnneal`)나 조기 종료가 필요하다.
- **MATLAB과 Python 차이**: 같은 방법에서 MATLAB 쪽 결과가 더 좋다(γ 폭, 마찰 교환, 실물형 20 ms). 출발점 SAC가 서로 다른 정책이고(MATLAB ck050, Python ck100) 시드도 하나씩이라, 학습기 차이인지는 가를 수 없다. 확인 필요.
- **Python PPO의 약점**: 마찰 교환(rev11 식별 마찰 0.40/0.12) 14~28/43, 실물형 20 ms 24~35/43. 실물 마찰이 11/23 측정보다 작으면 MATLAB 쪽 정책이 낫다.
- PPO를 처음부터(무작위 초기값) 학습하는 것은 이번에도 하지 못했다(앞 보고서: 1000회 0/16).
